# pixel-mv-director · 像素 MV 导演

**一套把一首歌做成像素风 MV 的规范（skill），语言无关、工具无关。**
**A language-agnostic skill for turning a song into a pixel-art music video.**

不是"一键生成器"，也不是"某段代码"。它规定的是一支像素 MV 该怎么被想出来、怎么被画、怎么被验收；
具体用什么语言、什么绘图库，由执行它的 agent 决定。

> Not a one-click generator, not a code dump. It defines how a pixel MV should be *thought of*, *drawn*, and *accepted* — the agent chooses the language and the drawing library.

---

## 它解决什么 / What it solves

| 常见做法 | 结果 | 本 skill |
|---|---|---|
| 让模型直接"生成像素风视频" | 滤镜感、像素块大小不一、人物生草 | 逻辑画布 + 整数放大，像素是画出来的 |
| 套一个现成叙事模板（双线 / 信物 / 播放器 UI） | 第一部像样，第二部像抄的 | 剧本从这首歌自己长出来：查原 MV / 读歌词 → 五幕 → 一句一镜 |
| 一上来写 40 个镜头 | 渲到一半发现停住、空洞、色场乱 | 7 项分镜校验挡在渲染前，硬错误直接拒渲 |
| 每个切点都上花式转场 | 节奏被打散，观众只觉得闹 | 转场择优：换幕必用，幕内按间隔和时长挑，全片 ≤ 切点的 34% |
| 靠眼睛判断"能不能发" | 反复返工 | 量化验收：0.2s 帧差 < 0.25% 判停住、脏色扫描、时长对齐 |

## 产出 / Output

```
音源 + LRC
   ↓  查原曲 MV（抽帧 / 测色 / 拆幕）或直接读歌词
剧本（五幕 + 每幕一句 intent）
   ↓  一句一镜
script.json  ← 唯一的故事来源，可手改
   ↓  7 项校验（硬错误不渲）

   ↓
封面 1146×717 + 标题 + 简介 + 标签 + 审计报告
```

## 三条最贵的规则 / Three rules that matter most

1. **逻辑低分辨率 + 整数放大。** 480×270 画，×4 到 1080p，只允许最近邻。非整数缩放或插值一圈就毁掉像素感。
2. **不做脸部大特写。** 这个画幅下全身/中景用剪影 + 边缘光才成立；程序化的脸在放大后必然"生草"。
3. **每镜必须自带运动。** 推近 / 平移 / 呼吸 / 光移，至少一种。0.2 秒内帧差 < 0.25% 就是"停住"，观众会以为卡了。

## 转场：择优，不是全用，也不是不用 / Transitions: earned, not sprayed

转场是标点，不是逗号。

| 位置 | 默认行为 |
|---|---|
| 换幕 / 换色场（现实 → 幻想 → 闭眼） | **必用** |
| 幕内，距上一个转场 ≥3 个切点，且该镜 ≥3.5s | 挑一个 |
| 全片转场数 | ≤ 切点数的 34% |
| 同一镜头的连续切换、正反打、情绪连续推近 | 硬切 |

8 种像素转场（溶解 / 棋盘 / 百叶 / 圆形 iris / 横扫 / 故障 / 涟漪 / 马赛克）的 mask 数学写在 `engine-spec.md` §7。
实现细节：**冻结上一镜的最后一帧**淡出，让下一镜正常播放——冻住入点会让人以为卡住。

## 快速开始 / Quick start

把这两样交给任意具备文件读写与命令行能力的 agent，并让它按本 skill 执行：

1. 音频文件（flac / mp3 / wav）
2. 歌词文件（`.lrc`，带 `[mm:ss.xx]` 行标）

> "用 pixel-mv-director 给这首歌做个像素 MV。先按 narrative.md 写剧本和 script.json 给我看，
> 我确认后再渲 30 秒预览。"

期望的第一次产出**不是视频**，而是：剧本（五幕 + intent）+ `script.json` + 校验报告。
确认剧本后再渲，能省掉"渲完才发现故事不对"。

## 为什么仓库里没有代码 / Why there is no code here

因为这类需求最大的浪费，是每个 agent 都从零发明一遍绘制层，然后各自踩同一批坑。

- 本仓库给的是**规范**：契约、阈值、判据、以及 50 多条"这样会翻车"的记录。
- 实现是**可替换零件**：`engine-spec.md` 的接口一一对应，任何语言实现出来行为等价（预计 500–900 行）。
- 这样它才能跨 agent 复用：Claude Code、Codex、Cursor、自建 agent，只要会画位图、会调 ffmpeg 就能跑。

如果你就是想要现成实现：按 `engine-spec.md` §2–§11 的顺序写，先 3 个镜头通链路，再铺量。

## 兼容 / Compatibility

| 需要 | 说明 |
|---|---|
| 位图绘制 | 能画实心矩形 / 多边形 / 椭圆 / 逐点线即可，不需要 GPU |
| 字体 | 一个日文字体 + 一个中文字体（可替换，路径写在配置里） |
| 视频 | ffmpeg（raw RGB 直写管道，不要逐帧落盘） |
| 音频分析 | 只需读时长 + 0.5s 窗 RMS 能量（可选 BPM） |
